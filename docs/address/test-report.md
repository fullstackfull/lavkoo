## Engines

The same CI test set ran against three real engines (the address tests build their tables with the real migrations, and `phpunit.mysql.xml` refuses a database whose name does not contain `test`). All three runs use the application's own database connection, which the platform configures **non-strict** (`'strict' => false` in `config/database.php`, as the production database runs): the servers' strict default does not apply to them.

| Engine | Result |
|---|---|
| MySQL 8.0.46 | 2,616 tests, 13,220 assertions, 0 failures, 3 skipped (37 minutes; the set includes `CiDatabaseTest`, which asserts that the job runs on MySQL 8) |
| MariaDB 11.4.2 (the version of the pilot server) | 2,615 tests, 13,220 assertions, 0 failures, 2 skipped (21 minutes) |
| MariaDB 10.11 | 2,615 tests, 13,220 assertions, 0 failures, 2 skipped (21 minutes) |

Running the new and changed tests on the real engines found two things SQLite hides, both in the tests and both fixed: a fixture table without the `coupon_code` column that SQLite read as a text value (a double-quoted unknown name), and a strict comparison of a JSON column's keys that MySQL lists in its own order. No product code was involved. A first attempt at the runs on the tested commit was discarded: the disk of the machine they ran on filled up and made tests fail with write errors, so they were stopped, space was freed, the databases were created again and all three runs were repeated from the start.

## What was not run

* **No production or staging system was touched.** Nothing was deployed, no migration was run on a real store database, and no provider (Torod, M5AZN) was contacted.
* **The real store schema.** The core tables come from a proprietary dump that is not in the repository: the tests rebuild them from inferred columns (`BuildsFulfillmentSchema`, `Builds*AddressSchema`). The compatibility of the four migrations with the live `shipping_addresses`, `orders` and `provider_cities` tables is covered by their `hasTable`/`hasColumn` guards and by the read-only `address:status`, `fulfillment:preflight` and `fulfillment:compatibility` commands the runbook has you run before and after; it is not proven here.
* **Torod's real responses** (paging, `returnAll`, ids v2 versus v5). The sync is tested against scripted fixtures of every behaviour we could think of (10 cities with a larger total, ignored `pageSize`, repeated page, zero-based paging, mid-run failure, empty list, ceilings, time budget); which one is true is a question for LogesTechs.
* **Real devices.** No physical phone, no real mobile app build, no Safari/Firefox; Chromium only (desktop 1100–1280 px and 375–390 px, LTR and RTL).
* **The picker's behaviour in CI.** Only its syntax is checked by the PHP suite (see above); its behaviour was verified in Chromium by hand.
* **The auction claim checkout** (its page is a view of this repository and still asks for a typed city and ZIP; the module route that saves it is not here) **and external order import** (no importer of external orders is in this repository).
* **National Address existence checks** (SPL's lookup API needs a key; only the published shape is enforced).
* **A country the store does not list.** The server reads Saudi Arabia in its many spellings and treats any other text as another country (open decision 11 in the README).
* **Load and performance** at production volumes (the old-address review reads typed cities once per distinct text and the page caps its live reading at 2,000 distinct texts).
* **The website's order completion end to end.** `StorefrontOrderCompletionTest` pins the refusals (the three completion endpoints, in front of any write); a completed website order is covered through the same order writer by the REST and payment-callback tests, not by a browser-driven checkout.

## Mutation checks

Where a rule protects data or a shipment, the corresponding tests were run against a deliberately broken copy of the code (a throw-away checkout, never the working tree) to prove they fail:

* **Earlier waves:** the Torod resolution and sync rules (19 mutations: shared-city claim, already-mapped check, silent replace, region contradiction, sync verdict, person decisions, repeated page counted as full, partial marking cities missing, total not reached, state used as a second city guess, stale mapping, ambiguous collapse, address text in a hold detail, district dropped, National Address sent, scrub gap), the panel edit (structured input dropped, ZIP always written, guest filter removed) and the shared picker (10 regression checks that fail on the previous script).
* **Review wave 3** (each caught by the tests that name it): a usable city that ignores its region; `address:mode` trusting the cached setting; the typeahead throttle without its own bucket; a dry run that counts every spelling; a rollback that drops a column that is not ours; the old-address confirmation and a rejection that do not retry a duplicate key; a refused checkout without its field prefix; no completion notice for an old address; the Torod decisions sharing one throttle bucket; a saved-address edit that writes from a stale read; and seven mutations of the picker (an exact name left with Tab thrown away, re-choosing the same region wiping the city, no request timeout, no field marking on a refused request, the list not named by its label, the disabled city box without its region-first text, the status text inside the list) — each fails the browser checks.
* **Test-quality review:** each of the three address guards of the website's order completion removed in turn; the order writer's amount, initial amount, shipping cost, discount and tax broken one by one (5); an address with a city but no National Address copied as a structured one; a syntax error in the picker script; the directory-columns check dropped; the country comparison without punctuation or without spaces removed; a wrong city for `Riyad` and for the Hofuf spellings in the alias file; the previous typeahead ranking (a village spelled like the alias first); the name of a city always in English or always in Arabic; a phrase deleted from the Arabic language file; the previous picker (no click handler) against the real-mouse check. Every one of them fails the tests it should.
* **Final review:** the retry of a city edit without putting the model back (three tests fail: a deadlock on the first statement, on the last, and one that never ends); a data row that is not an object in a cities or aliases file (a TypeError); the saved address's city when an order's copy names none; and 13 of the 24 new browser checks fail on the previous picker and Torod-page scripts (a click after a failure, the list opening on the chosen city and Enter keeping it, Escape and a choice dropping a pending search, a refusal stacking its message and its id, a stale answer or failure on the Torod manual match).
