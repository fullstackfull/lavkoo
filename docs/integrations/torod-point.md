# Torod Point (LogesTechs) — our fulfillment warehouse

Company ID **714** (pre-filled in the settings form as a suggestion; it is not a secret and is never taken from an
API example). Two API families, with strictly separate jobs:

| API | Base URL (default, editable, host-restricted to `logestechs.com`) | Used for |
|---|---|---|
| **Fulfillment API v5** | `https://apisv5.logestechs.com/api` | Warehouse **products**, **matching/sync**, and **creating warehouse (fulfillment) orders** |
| **Lastmile API v2** | `https://apisv2.logestechs.com/api` | **Helper only:** cities, package status, cancel package, air waybill |

> **No duplicate shipments.** A warehouse order makes the *warehouse* pick, pack and ship, and it creates its own
> last-mile package. The Lastmile "create shipment" call is therefore **never made** — calling both would ship the
> parcel twice. The capability report lists it as *Deliberately not used*.

## Credentials (Admin → Fulfillment providers → Torod Point)

* **Fulfillment API (v5):** username + password, sent as `company-id` / `username` / `password` headers.
* **Last-mile API (v2):** email + password (login), used only for the helper calls above.
* **Webhook secret:** generated by the system (**Generate webhook secret**); the URLs are shown in full once.

All are stored encrypted, are write-only in the UI, and never appear in logs.

## Matching our products to warehouse products (explicit, never automatic)

1. **Sync warehouse products now** (or the 30-minute schedule) stages the warehouse product list.
2. **Torod Point matching** lists each warehouse product with *suggestions* (same SKU, same barcode, warehouse
   reference equal to the store product id) and the reason for each.
3. A person **approves** a match → `provider_product_mappings` (one warehouse product ↔ exactly one store product;
   a barcode alone never decides ownership because the same barcode may exist under another provider).
4. Approving a match **does not** assign the product to Torod Point. Tick *Also assign this product to Torod Point*
   or use the **Fulfillment provider** card on the product form; that goes through the assignment rules.
5. Name, SKU and barcode similarity are only ever suggestions.

## Pushing store products to the warehouse (off by default)

Enable *Allow pushing products to the warehouse*; **Push** uses Product Bulk Upsert. Dry run shows exactly what would
be sent. Only an allow-listed set of fields can come from the defaults JSON; **quantity and identity fields are never
sent**, so we never set warehouse stock. A product assigned to another provider (M5AZN) is **skipped** by a push, with the reason
shown, and so is one whose mapping the assignment rules refuse: a push never takes a product away from the provider that owns it.

## Orders

Eligible orders (paid or COD; status in the configured dispatch statuses; Torod-owned lines only) are sent
automatically through the queue as warehouse orders. Held — not sent — when: a product has no approved match, the
city is not a Torod Point city (see aliases), the phone is not a valid Saudi number, the address is incomplete, a COD
collection method is not configured, or an amount cannot be converted to SAR. Our own **invoice number** is the order
reference (`{order id}-TP{generation}`), which is also how an ambiguous submission is found again.

## Status and tracking

* **Lastmile webhook** (package statuses) drives the shipment status. **Fulfillment webhook** (`CREATED`, `PICKED`,
  `PACKED`) only updates *Warehouse status* for display: **packing is never delivery.**
* The webhooks are **unsigned**, so the secret in the URL is the only credential: give LogesTechs both URLs
  (`/api/fulfillment-webhooks/torod-point/{secret}/lastmile` and `…/fulfillment`), keep them private, and rotate on
  suspicion. A `delivered` / `cancelled` claim is **checked with the package-status call** before it is applied;
  a claim that cannot be checked waits. An optional IP allow-list is available if LogesTechs publishes source IPs.
* `fulfillment:poll` (every 15 min) is the safety net for webhooks that never arrive.

## Cancellation

Cancellation exists only on the Lastmile API, against the **package the warehouse creates**. Once that package's
barcode is known (it arrives with the first webhook) *Cancel at the provider* calls it, and the cancellation is final
only when Torod Point reports the package cancelled. **Before the package exists no cancel call is documented**, so
the request is reported as unsupported: cancel it in the Torod Point dashboard, then press *Mark cancelled by hand*
on the shipment page (a reason is required and recorded).

## Stock

See the [stock question](capability-matrix.md#the-stock-question-brief-item-4): no documented inventory endpoint and no
documented stock field. Stock stays *manual* (labelled) until LogesTechs confirms the field and an administrator
verifies the map **and** ticks the confirmation.
