# Changes to files that existed before this work

Everything else is new (new directories `app/Services/SalesChannels`, `app/Services/OperationalCosts`, the migrations dated `2026_11_07_*` to `2026_11_11_*`, models, enums, commands, tests, docs). The Torod Point / M5AZN workstream (`app/Services/Fulfillment/**`, `app/Http/Controllers/Admin/Fulfillment/**`, `routes/admin/fulfillment.php`, `RouteServiceProvider`) is **not modified**. `main` (including its Hotfix 2 and the unified-address work of PR #4, merge commit `0bcabe8`) was merged into this branch with a merge commit and without a conflict; the combined Fulfillment, address, sales-channel and cost suites pass.

The two files of the platform's own order logic that are touched (`OrderManager`, `OrderRepository`) are touched by a guard only, see the table: they are the one place where this work changes how an existing order behaves, and only for an order that was made for a channel order.

| File | Change | Why |
|---|---|---|
| `bootstrap/providers.php` | one line: `SalesChannelsServiceProvider` | registers the module's routes, rate limiter and null extension points without touching `RouteServiceProvider` |
| `app/Enums/GlobalConstant.php` | two keys in `EMPLOYEE_ROLE_MODULE_PERMISSION`: `sales_channels`, `operational_costs` | the new permissions appear in the role editor |
| `app/Console/ScheduleDefinition.php` | one block: `channels:sync --due` (5 min), `channels:publish --only=stock,price,shipments` (15 min), `channels:publish --only=allocate` (every 5 min, at :02), `channels:publish --only=settle` (10 min), `channels:dispatch` and `channels:dispatch-sync` (5 min), `channels:find-shipments` (10 min), `channels:purge-buyer-data` (hourly), `channels:prune` (daily), and `costs:refresh --days=3` (hourly) and `costs:accrue-storage` (daily) **only while `OPERATIONAL_COSTS_ENABLED` and `OPERATIONAL_COSTS_SCHEDULE_ENABLED` are both on** (both off by default) | the channel commands do nothing until `SALES_CHANNELS_ENABLED` is on and an account is enabled (dispatch and discovery also need their own switches); the cost commands are absent from the schedule until the owner switches them on; `channels:prune` and `channels:purge-buyer-data` only delete and have no switch; each command no-ops before the migrations. No purchase-order command is scheduled |
| `app/Utils/OrderManager.php`, `app/Repositories/OrderRepository.php` | in the status-change stock function of each, a guard through `ChannelOrderMarker::holdsNoStock($order)`: for an order made for a channel order only the lines' delivery status follows the new status | the order took nothing from `products.current_stock` (its lines are marked `is_stock_decreased = 0`), and the platform's own code treats every status but returned/failed/canceled as "stock taken": without the guard the first manual move of the order would take the units off the store's stock, and cancelling it would give back units never taken |
| `phpunit.xml`, `phpunit.mysql.xml` | one `<server>` line each: `OPERATIONAL_COSTS_ENABLED=true` | the cost module ships off; the module's tests (and the platform's, which do not care) run with the master switch on, and the tests of the off state set it off themselves |
| `tests/CreatesApplication.php` | with `DB_STRICT_TESTS=1` the test connection to MySQL/MariaDB is put in strict mode | the application's own connection is not strict, so the strict-mode CI job and the local strict runs prove the new code writes nothing a strict server would refuse |
| `tests/Feature/CiDatabaseTest.php` | the expected server version is the one the job declares (`EXPECT_DB_VERSION`, default `^8\.` as before) | the CI jobs now run on MySQL 8 and on MariaDB 11.4.2 |
| `resources/views/layouts/admin/partials/v2/_rail.blade.php`, `_side-bar.blade.php` | a rail button and a sidebar section "Sales Channels" (shown only to holders of the two permissions, links guarded by `Route::has`) | navigation |
| `resources/lang/{en,sa,ae}/new-messages.php` | added keys only (English, Saudi Arabic, Emirati Arabic): no line that existed in `main` is changed or removed | every visible phrase is translated; a test fails on any missing key |
| `bootstrap/app.php` | `'secrets'` added to the existing `dontFlash` list | the account form's `secrets[...]` inputs are never flashed back into the session after a validation error |
| `.github/workflows/ci.yml` | `workflow_dispatch` (a manual run on any branch); the existing database job (`tests-mysql`, the Fulfillment + security and Address groups) now also runs on MariaDB 11.4.2, and every database job declares the engine version it must run on; the leak guard falls back to `origin/main` for a manual run; two jobs added at the end of the file: `tests-mysql-sales-channels` (the modules on MySQL 8.0 and MariaDB 11.4.2 in two groups, with the multi-process concurrency tests) and `tests-strict-mode` (MariaDB 11.4.2 with the test connection in strict mode) | MariaDB 11.4.2 is the engine the pilot server reports; the module list is long (a long run on a runner), so it has its own jobs and limits instead of lengthening the Fulfillment job. The sibling workstream's test lists in the shared job are unchanged |

No `composer.*`, `Modules/` or `public/` file is touched, so the deploy overlay builder accepts the release.
