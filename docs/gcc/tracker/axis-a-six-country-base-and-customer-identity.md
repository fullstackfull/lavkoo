#### A1-02. Each market opens and closes on its own, with a safe way to switch one off

- **State: IN PROGRESS** | plan lines 182 | DECISIONS (countries activated independently, store configurable while inactive, suspension keeps obligations); GCC-12; STOREFRONT_FLAG_RUNBOOK | reviews: owner-decision, security
- **(2) Functional requirement.** A market can be prepared while inactive and opened on its own. An inactive market is never served, and switching one off must not break payments, orders and refunds already started in it.
- **(3) Exists now in code (main).** On main: the per-market `active` key, the resolver ignoring inactive markets, and the whole lifecycle of I2-11 -- `App\Services\Storefront\StorefrontLifecycle` (draft, ready, active, paused in three modes), its readiness gate `StorefrontPreflight` (legal texts, their independent review, the currency, the selling company, the tax decision), `php artisan gcc:storefront:state` and the admin screen behind it, each change recorded with who, when, why and a reference, in the same transaction as its audit line. Turning the master flag off still removes the narrowing from everything, which is the hazard criterion 3 names and which (5) now explains rather than proposes.
- **(4) Done in the draft PRs.** PR 19: per-market active key (only SA true); the resolver ignores inactive markets in query, header and path and refuses an inactive default. PR 53: the kill switch is to deactivate the country, not to turn the flag off (runbook, StorefrontKillSwitchTest); a payment started in a market later switched off or removed is still finished there.
- **(5) What remains.** Two things, and both are decisions rather than lines of code.

  **Reachability still comes from the configuration alone.** A market the configuration does not list as `active` stays unreachable however the lifecycle records it, so opening a country that was not shipped active needs a deploy. Two levels exist on purpose -- the configuration says which countries this installation is built to serve, the lifecycle says which of them are open for business -- but the second can read ACTIVE while the first keeps the market unreachable, which is one switch too many. Wiring the two together was tried on this branch and backed out: `StorefrontResolver` is a container-free value object that several callers build directly (its own unit tests run with no application at all), and `fromConfig()` is called many times per request, so reading a record inside it costs a settings lookup per configured market per resolve, and a schema probe where the lifecycle has not been resolved before. It needs either a denormalised index the lifecycle writes when it opens a market (one lookup), or one read per request handed to the resolver. Worth doing; worth doing deliberately.

  **The flag-off hazard: settled by the owner on 2026-11-24, and guarded.** Legacy mode wins, the switch is not a kill switch, and the state it creates is one the platform must not be operated in: `gcc:storefront:safety` reports it, the actions that would open a market refuse while it holds, and the way out is never blocked. What follows is the record of how it was settled.

  **It was a conflict between two promises.** Criterion 3 asks that turning the master flag off cannot expose another country's products. The programme's other promise is that while the flag is off the platform is byte-for-byte the platform of today -- nothing narrowed anywhere -- and that one is pinned deliberately, in dozens of tests, by name: `StorefrontByIdReadsTest::test_while_storefronts_are_off_every_product_answers_as_before` reads a Kuwaiti product through the Saudi storefront's API and asserts it answers. Making the flag a kill switch was implemented on this branch and backed out, having proved the point: narrowing the READS while the flag is off is safe for a Saudi installation (every product of it carries `SA`, the column's own default, and the rows that name none are kept), but it contradicts that promise wherever a test's world holds a foreign product, and it must NOT be extended to the cart's own gate (`StorefrontCatalog::offers`, which compares a column on a row the caller already loaded -- a row loaded without that column would be refused, which would stop a Saudi installation selling its own products). Which promise wins is the owner's call. The safe remedy exists and is documented: switch the COUNTRY off, not the flag (criterion 2 of this requirement, and the runbook).
